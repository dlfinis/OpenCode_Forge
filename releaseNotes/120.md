## 1.2.0

### New Features

- **Typed Server Health Check**: `/api/info` responses are now classified as healthy, auth-required, foreign service, or not responding. A non-OpenCode service listening on the same port is no longer mistaken for a live server, and auth failures no longer trigger automatic restarts.
- **Server Lifecycle Ownership**: local servers are now classified as `OWNED`, `SHARED`, `ATTACHED`, or `REMOTE`. The Stop action only terminates servers started by the plugin itself; shared v2 services are disconnected, never killed.
- **Conservative Auto-Revive**: before re-attaching to a shared v2 service, the plugin re-resolves its identity (pid, url, password from `service.json`). If the identity changed or the registry is unreadable, the user is notified instead of silently spawning a private replacement.
- **Version Gate**: after connecting, the plugin reads `/api/info` and warns once per project when the OpenCode server is not a v2 major version.
- **Service Discovery Cache**: discovery results are cached with a 3-second TTL and merged concurrent requests (single-flight), with a bounded global deadline when reading `service.json`. Cache invalidates on health failure, auth rejection, and service stop/restart.
- **Windows CLI Resolution**: on Windows the plugin now resolves the real executable behind `opencode` shims (`.cmd`) and builds terminal commands according to the detected shell family (bash vs PowerShell/cmd).
- **v2 Diff Contract**: file diffs are reconstructed from the v2 `patch` field; the legacy `before`/`after` contract is no longer relied upon.

### Fixes

- **Single JCEF Browser per Web Tab**: the web file editor provider is now registered only in the optional JCEF config file. Registering it in both `plugin.xml` and the optional config created two browser instances per web tab.
- **Removed Process-Environment Credential Scanning**: authentication no longer scans spawned process environments for `OPENCODE_SERVER_PASSWORD`. Credentials come from the shared `service.json` or the user (managed password flow).

### Compatibility

- Verified against OpenCode **v2.2.0** (service discovery, `/api/info` bare response shape, `patch`-based diffs, absence of the removed `POST /tui/append-prompt` endpoint).
- macOS/Linux behavior is unchanged by the Windows CLI resolver; existing shortcuts and plugin id are preserved.
