## 1.2.4

### Changed

- **The plugin no longer spawns its own server.** When nothing is listening, it runs
  `opencode service start`, waits for the background service to register, and attaches to it.
  OpenCode v2 already owns that lifecycle: the service writes its endpoint and credentials to
  `service.json`, and every client resolves them from there.

  What this removes: a duplicate `opencode serve` process per IDE window, a password generated by
  the plugin, and that password typed into the terminal — where it ended up in the shell history.
  With the shared service the terminal command is just `opencode --continue`.

### Fixes

- **The CLI's own error is shown when the service cannot start.** `opencode service start` reports
  actionable failures, for example a configured port already held by another process. That text was
  discarded and the user only saw a generic message.
- **Build output and IDE internals are no longer tracked as changes.** The diff pipeline had no path
  filter, so it captured the content of every file the IDE touched — including its own index files
  when the project contained an IDE sandbox. `.git`, `.idea`, `.gradle`, `.intellijPlatform`,
  `.kotlin`, `build`, `out` and `node_modules` are skipped at the project root; `build.gradle.kts`,
  `.gitignore` and nested directories of the same name stay tracked.

### Compatibility

- Built against IntelliJ IDEA 2025.2.4 (`sinceBuild` 252). Supported IDE range is unchanged.
